# ЛАБОРАТОРНА РОБОТА 1

# СКЛАДАННЯ MASTER TEST PLAN ДЛЯ GAMESINFOSYS

Джерело-основа: `Лабораторна робота 1 1.pdf`.

## Мета

Навчитися формувати тест-план для вебсистеми, що взаємодіє із зовнішніми API і локальною базою даних.

## Хід роботи

### 1 Вступ

Цей документ визначає перевірку GamesInfoSys. Метою є підтвердження коректності користувацьких сценаріїв, інтеграцій, локального збереження і поведінки за відсутності зовнішніх даних.

### 2 Об'єкти тестування

- головна сторінка;
- каталог;
- пошук;
- картка гри;
- форма Steam App ID;
- таблиця пропозицій;
- перерахунок UAH;
- локалізація;
- SQLite;
- RAWG/demo;
- Steam;
- CheapShark;
- НБУ.

### 3 Функції, що тестуються

- відкриття сторінок;
- пошук за частиною назви;
- відображення demo-набору;
- отримання live-даних;
- показ метаданих;
- збереження Steam App ID;
- створення та оновлення `StoreOffer`;
- додавання `OfferPricePoint`;
- конвертація валют;
- перемикання мови;
- зовнішні переходи.

### 4 Функції, що не тестуються

- реальна купівля гри;
- платіжні сервіси;
- авторизація користувачів;
- push-сповіщення;
- промислове масштабування.

### 5 Підхід

| Вид | Призначення |
|---|---|
| smoke | перевірити запуск і базові сторінки |
| модульне | перевірити чисту логіку |
| інтеграційне | перевірити HTTP і SQLite |
| системне | перевірити повний маршрут |
| негативне | перевірити некоректні ID, URL і збої |
| регресійне | повторити критичні сценарії |
| usability | оцінити зрозумілість UI |

### 6 Критерії проходження

Тест пройдено, якщо:

- немає необробленої помилки;
- відображено очікуваний стан;
- дані не дублюються;
- зовнішній збій не руйнує сторінку;
- користувач отримує зрозуміле повідомлення.

### 7 Критерії зупинки

- застосунок не збирається;
- стартова сторінка недоступна;
- база не створюється;
- критична помилка повторюється у більшості сценаріїв.

### 8 Результати

- тест-план;
- тест-кейси;
- матриця вимог;
- журнал результатів;
- дефекти;
- підсумковий висновок.

### 9 Завдання тестування

1. Підготувати середовище.
2. Зібрати проєкт.
3. Очистити або скопіювати тестову SQLite.
4. Виконати smoke.
5. Виконати функціональні сценарії.
6. Перевірити негативні випадки.
7. Повторити регресію.
8. Оформити звіт.

### 10 Середовище

| Параметр | Значення |
|---|---|
| Runtime | .NET 10 |
| СКБД | SQLite |
| UI | Chromium-браузер |
| Дані | demo і live |
| Мова | українська, англійська |

### 11 Ризики

| Ризик | Дія |
|---|---|
| RAWG недоступний | використати demo |
| магазин змінив API | зафіксувати відповідь і адаптувати |
| нестабільний інтернет | відокремити локальні та live-тести |
| база містить старі дані | використовувати копію |
| курс НБУ недоступний | перевірити вихідну валюту |

## Висновки

Під час роботи сформовано Master Test Plan, що охоплює функціональність, інтеграції, дані й інтерфейс GamesInfoSys. План враховує характерну для системи залежність від зовнішніх джерел і передбачає demo-режим як механізм стабільної перевірки.
