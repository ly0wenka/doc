# ЛАБОРАТОРНА РОБОТА 3. ТЕСТ-КЕЙСИ ТА МАТРИЦЯ ТРАСУВАННЯ GAMESINFOSYS

Джерело-основа: `Лабораторна робота 3.docx`.

## Мета

Навчитися формувати відтворювані тест-кейси і перевіряти покриття вимог.

## Структура тест-кейсу

| Поле | Зміст |
|---|---|
| ID | унікальний код |
| Назва | коротка перевірювана дія |
| Вимога | пов'язаний REQ |
| Передумови | стан системи |
| Дані | конкретні значення |
| Кроки | послідовність |
| Очікуваний результат | критерій успіху |
| Фактичний результат | після виконання |
| Статус | Pass, Fail, Blocked |

## Завдання

1. Створити позитивні тести пошуку.
2. Створити негативні тести Steam URL.
3. Перевірити demo-режим.
4. Перевірити SQLite upsert.
5. Перевірити валюту.
6. Перевірити локалізацію.
7. Побудувати матрицю `Requirement x Test Case`.

## Правила трасування

- кожна Must-вимога має хоча б один тест;
- високоризикова вимога має позитивний і негативний тест;
- тест не повинен перевіряти декілька незалежних функцій без потреби;
- статус вимоги визначається результатами всіх пов'язаних тестів;
- зміна вимоги потребує перегляду тестів.

## Формула покриття

`Coverage = TestedRequirements / TotalRequirements * 100 %`.

Рекомендований критерій для базових вимог GamesInfoSys - 100 %.
